# 在线文档系统 —— 变现规划与功能增强方案

## 一、概述（Summary）

本项目是一个功能已具雏形的在线文档协作系统（类飞书 / 腾讯文档），已实现：多用户认证、表格 / 富文本两类文档、实时协作（WebSocket + Yjs）、按用户 / 链接分享、表格导出 xlsx、编辑日志。

要实现商业变现，核心思路是 **从"免费工具"转向"分层订阅（Freemium）+ 增值服务"** 的 SaaS 模式。本方案分析当前可变现基础、给出推荐的商业模式，并列出为支撑变现 **必须补齐的功能模块**，按优先级分批实施。

## 二、当前状态分析（Current State Analysis）

### 已有能力（可作为变现基础）
| 能力 | 位置 | 变现相关性 |
|---|---|---|
| 用户体系 | [auth.ts](file:///f:/code/project/在线文档系统复刻/src/server/auth.ts) / users 表 | 账户是计费主体，基础已具备 |
| 文档 CRUD | [documents/route.ts](file:///f:/code/project/在线文档系统复刻/src/app/api/documents/route.ts) | 可按文档数 / 存储量计费 |
| 实时协作 | [roomHub.ts](file:///f:/code/project/在线文档系统复刻/src/server/ws/roomHub.ts) | 可按协作人数 / 在线人数分层 |
| 分享（用户+链接） | [access.ts](file:///f:/code/project/在线文档系统复刻/src/server/access.ts) / [ShareDialog.tsx](file:///f:/code/project/在线文档系统复刻/src/components/ShareDialog.tsx) | 高级分享（密码、有效期）可作付费点 |
| 导出 xlsx | [export/[id]/route.ts](file:///f:/code/project/在线文档系统复刻/src/app/api/export/%5Bid%5D/route.ts) | PDF / Word 等高级导出可付费 |
| 编辑日志 | document_edit_logs 表 | 版本历史 / 审计可付费 |

### 关键缺口（阻碍变现）
1. **无任何计费 / 订阅体系** —— 没有套餐、订单、支付、额度概念。
2. **无团队 / 组织概念** —— 只有个人用户，无法做 B 端团队版（客单价最高的场景）。
3. **无用量配额与限制** —— 无法区分免费与付费用户的权益边界。
4. **无权限分级钩子** —— 现有 `access.ts` 只判断读写，未接入"功能是否被套餐允许"。
5. **数据层是单机 SQLite** —— 无法支撑规模化付费用户（需评估迁移）。

## 三、推荐商业模式（Monetization Strategy）

采用 **Freemium 分层订阅** 为主，辅以增值一次性服务：

### 套餐设计（建议）
| 套餐 | 定价方向 | 权益边界（用配额控制） |
|---|---|---|
| **免费版 Free** | ¥0 | 文档数 ≤ 20、单文档协作人数 ≤ 3、存储 ≤ 100MB、仅 xlsx 导出、版本历史 7 天 |
| **专业版 Pro**（个人） | 月付 / 年付 | 文档无限、协作人数 ≤ 10、存储 ≤ 5GB、PDF/Word 导出、版本历史 30 天、分享链接加密+有效期 |
| **团队版 Team**（组织） | 按席位（seat）月付 | 团队空间、成员管理、权限组、审计日志、无限版本历史、优先协作节点 |

### 增值点（可选一次性 / 加购）
- 超额存储包、AI 辅助写作 / 表格公式（调用大模型，按量计费）、去除水印、自定义域名 / 品牌白标。

## 四、为支撑变现需新增的功能（Proposed Changes）

> 按优先级分为 **P0（变现闭环必需）→ P1（提升转化）→ P2（B 端扩展）**。每项含：改什么、为什么、怎么做。

### P0-1：订阅 / 套餐数据模型
- **What**：在 [db.ts](file:///f:/code/project/在线文档系统复刻/src/server/db.ts) 新增表：
  - `plans`（套餐定义：code、name、price、限额 JSON）
  - `subscriptions`（user_id / org_id、plan_code、status、当前周期起止、支付渠道单号）
  - `usage_counters`（主体、指标 doc_count/storage_bytes、当前值，用于配额校验）
- **Why**：所有计费与权限判断的基础，没有它无法区分付费 / 免费。
- **How**：沿用现有 `better-sqlite3` 建表风格与 repo 模式（参考 `docsRepo` / `sharesRepo`），新增 `plansRepo` / `subscriptionsRepo` / `usageRepo`。

### P0-2：配额校验与功能门禁（Entitlement）
- **What**：新增 `src/server/entitlement.ts`，提供 `checkQuota(user, 'doc_count')`、`canUseFeature(user, 'export_pdf')` 等函数。
- **Why**：把"套餐权益"落到每个受限动作上，是免费 / 付费差异的执行点。
- **How**：
  - 在 [documents/route.ts](file:///f:/code/project/在线文档系统复刻/src/app/api/documents/route.ts) 的 `POST`（新建文档）处校验文档数配额；
  - 在 [roomHub.ts](file:///f:/code/project/在线文档系统复刻/src/server/ws/roomHub.ts) 的 `addClient` 处校验协作人数上限；
  - 复用 [access.ts](file:///f:/code/project/在线文档系统复刻/src/server/access.ts) 的判定链路，在其后追加"套餐功能门禁"层。

### P0-3：支付集成
- **What**：新增支付 API 路由 `src/app/api/billing/`：
  - `create-checkout`（创建支付订单，返回支付链接 / 二维码）
  - `webhook`（接收支付回调，激活 / 续期 `subscriptions`）
  - `portal`（用户查看 / 取消订阅）
- **Why**：变现的收款闭环，缺此无法真正收钱。
- **How**：国内首选 **微信支付 / 支付宝**（Native/JSAPI），海外可选 Stripe。Webhook 内做验签 + 幂等，成功后更新订阅状态。**支付密钥走 `.env`**（参考现有 `SESSION_SECRET` 约定）。

### P0-4：定价页与升级入口（前端）
- **What**：新增 `src/app/pricing/page.tsx` 定价页；在 [DocumentsClient.tsx](file:///f:/code/project/在线文档系统复刻/src/components/DocumentsClient.tsx) 顶栏用户菜单加"升级 / 我的订阅"入口；触达配额上限时弹出升级引导。
- **Why**：转化路径，让用户知道买什么、在哪买。
- **How**：复用现有 Tailwind 卡片 / 弹窗风格（参考 `AuthModal`、文档卡片布局），配额拦截时以 Modal 形式提示"升级解锁"。

---

### P1-1：高级分享（付费点）
- **What**：扩展分享链接支持 **访问密码、有效期、禁止下载**。需在 documents 表补 `share_password_hash`、`share_expires_at` 字段。
- **Why**：企业用户高频付费诉求，转化 Pro 的强钩子。
- **How**：改 [share-link/route.ts](file:///f:/code/project/在线文档系统复刻/src/app/api/documents/%5Bid%5D/share-link/route.ts) 与 [access.ts](file:///f:/code/project/在线文档系统复刻/src/server/access.ts) 的 token 校验分支，加入过期 / 密码校验；UI 在 [ShareDialog.tsx](file:///f:/code/project/在线文档系统复刻/src/components/ShareDialog.tsx) 的 link tab 增加对应选项（免费版置灰 + 升级引导）。

### P1-2：高级导出（付费点）
- **What**：新增 PDF / Word 导出；富文本文档导出（当前仅表格支持 xlsx）。
- **Why**：明确的功能差异点，易于打包进 Pro。
- **How**：新增 `src/app/api/export/[id]/pdf` 等路由，服务端渲染导出；入口在编辑器工具栏，免费版仅开放 xlsx。

### P1-3：版本历史 / 快照回滚
- **What**：将 `document_snapshots`（当前仅存最新）扩展为多版本表 `document_versions`（保留 N 天历史），提供版本列表与回滚。
- **Why**：既是核心留存功能，也是分层权益（免费 7 天 / Pro 30 天 / Team 无限）。
- **How**：在 [roomHub.ts](file:///f:/code/project/在线文档系统复刻/src/server/ws/roomHub.ts) 的 `scheduleDocSave` 落库时追加历史版本；按套餐保留时长清理；新增版本管理 API 与编辑器侧边栏。

---

### P2-1：团队 / 组织（B 端最高客单价）
- **What**：新增 `organizations`、`org_members`（角色 owner/admin/member）表；文档可归属组织；订阅主体从 user 扩展到 org（按席位计费）。
- **Why**：B 端团队版是 SaaS 收入主力，客单价远高于个人。
- **How**：数据模型上给 documents 增加可选 `org_id`；`listAccessible` 与 `access.ts` 增加组织维度；新增团队管理页与成员邀请。

### P2-2：审计日志与后台
- **What**：基于现有 document_edit_logs 扩展为完整审计（登录、分享、导出、成员变更），提供管理后台查看。
- **Why**：企业合规刚需，Team 套餐卖点。
- **How**：扩展 `logsRepo` 记录更多事件类型；新增后台页（受组织 admin 权限保护）。

### P2-3：数据层与部署评估
- **What**：评估 SQLite → PostgreSQL 迁移，以支撑规模化付费与并发。
- **Why**：单机 SQLite 在多付费用户 / 高并发协作下是瓶颈与单点风险。
- **How**：抽象 repo 层（当前已较集中于 [db.ts](file:///f:/code/project/在线文档系统复刻/src/server/db.ts)，迁移成本可控），逐步替换驱动。**此项为评估，非立即实施。**

## 五、假设与决策（Assumptions & Decisions）

- **假设**：目标市场以国内为主，故支付优先微信 / 支付宝；如面向海外再加 Stripe。
- **决策**：采用 Freemium 分层订阅为主模型（对本项目形态最匹配，转化路径清晰）。
- **决策**：先做个人 Pro（P0+P1）跑通收款闭环，再做团队版（P2）——避免一开始就上重型组织模型。
- **假设**：短期内 SQLite 可继续使用，规模化后再迁移（P2-3 仅评估）。
- **待用户确认项**：具体定价数字、优先海外还是国内支付、是否需要 AI 增值功能。

## 六、验证步骤（Verification）

1. **数据模型**：建表后用脚本插入测试套餐 / 订阅，验证 repo 读写正确。
2. **配额门禁**：以免费账户创建超过限额的文档 / 拉起超额协作人数，确认被拦截并弹升级引导。
3. **支付闭环**：用支付沙箱环境完成一次下单 → webhook 回调 → 订阅激活 → 权益解锁全流程。
4. **降级 / 过期**：模拟订阅到期，确认权益回落到免费版且数据不丢失。
5. **回归**：确认现有免费功能（新建、协作、分享、导出 xlsx）在引入门禁后不受影响。

---

## 七、实施顺序建议

```
第一阶段（变现闭环 MVP）：P0-1 → P0-2 → P0-3 → P0-4
第二阶段（提升转化）：    P1-1、P1-2、P1-3
第三阶段（B 端扩展）：    P2-1 → P2-2 →（评估）P2-3
```

完成第一阶段即可开始收款；第二阶段拉升付费转化率；第三阶段打开团队版高客单价市场。
