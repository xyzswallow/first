# 在线文档编辑系统 — 实现方案

## 摘要（Summary）

参照 `Lucky_sheet` 项目（Django + Channels/WebSocket + Redis + SQLite + Luckysheet），
用现代技术栈复刻并升级为一个优雅的 Web 在线文档系统。

技术栈：
- Next.js 16（App Router）
- React 19
- TypeScript 5
- Tailwind CSS v4
- SQLite（数据持久化）

在参考项目基础上的升级点（依据用户确认）：
- 文档类型：**表格 + 富文本文档 + 更多入口**（PPT / 思维导图等仅预留入口，暂不实现）
- 协作：**WebSocket 实时协作**（多人同时编辑同步）
- 账户与分享：**完整账户体系 + 两种分享**（按用户名分享 + 生成只读/可编辑分享链接）

## 参考项目现状分析（Current State Analysis）

来自解压分析（未落地文件，仅阅读）：

- 后端：Django 5.1 + `channels` + `daphne`（ASGI），Redis 作实时数据缓存与广播。
- 数据模型 `Lucky_sheetmodels/models.py`：
  - `Document(doc_id, doc_name, user, updated_at, share_token, share_permission)`
  - `DocumentShare(doc, shared_with, permission[read|edit])` — 按用户名分享
  - `DocumentEditLog(doc, user, username, edit_time, edit_type, ip, summary)` — 编辑日志
- 视图 `Lucky_sheet_views/views.py`：`login/register/logout/change_password`、
  `index`、`document_cover_page`（文档列表）、`upload_excel`、`get_document`/`save_document`（Redis 存取）、
  `delete_document`、`share_document`（按用户名）、`share_link`/`share_view`（链接分享）、`export_excel`（openpyxl 导出）。
- 实时协作 `consumers.py`：WebSocket 房间 `document_<doc_id>`，接收 gzip 压缩的操作数据，
  按 `t` 字段（`mv`/`v`/其他）分类型广播给同房间其他客户端；心跳 `rub`；最新快照存 Redis `doc_<doc_id>`。
- 前端 `templates/Lucky_sheet_.html`：加载 Luckysheet，`loadUrl` 拉快照、`updateUrl` 走 WebSocket 协作；
  自动保存（防抖）到 `save_document`；支持只读模式（`share_permission==read` 时 `allowEdit=false`）；导出/打印。
- 文档列表 `templates/document_cover.html`：卡片式"新建文档"、列表（文档名/更新时间/分享/删除）、链接分享弹窗。

结论：参考项目核心 = 账户 + 文档列表 + 表格编辑器 + WebSocket 实时协作 + 快照持久化 + 两种分享 + 导出。
本方案在此基础上新增"富文本文档"类型并预留更多类型入口，用 Next.js 全栈替代 Django。

## 目标架构（Target Architecture）

### 运行形态
- 采用 **自定义 Node 服务器**（`server.ts`）同时承载：
  1. Next.js 16 请求处理（App Router，SSR + API Route Handlers）
  2. 一个 `ws` WebSocket 服务器（实时协作），与 HTTP 共用同一端口，路径 `/ws`。
  - 原因：Next.js App Router 无内置 WebSocket 服务；自定义服务器是承载长连接最稳妥的方式，
    可完整复刻参考项目"房间广播 + 快照持久化"的协作模型，且无需引入 Redis（用内存房间 + SQLite 快照替代）。

### 数据层
- SQLite，使用 `better-sqlite3`（同步、零依赖、适合单机；建表脚本初始化）。
- 数据访问集中在 `src/server/db.ts`，导出预编译语句与仓储函数。

### 认证
- 自建**基于 Cookie 的会话**（`iron-session` 加密无状态会话，避免额外会话表）：
  - 注册（用户名+密码，`bcryptjs` 哈希）、登录、登出、修改密码。
  - 受保护路由通过服务端读取会话校验；分享链接匿名可访问（按 token 权限）。

### 文档模型（多类型）
- 统一 `documents` 表，`type ∈ {sheet, doc}`（`ppt`/`mindmap` 预留枚举但不实现编辑器）。
- 文档内容以 JSON 快照存储于 `document_snapshots.content`（表格=Univer/网格快照；富文本=Tiptap JSON）。

### 编辑器选型
- **表格**：`@univerjs`（Luckysheet 官方继任者，TS/React 原生、现代化 UI）。
  - 协作：监听 Univer `commandService` 的 mutation，将操作通过 WebSocket 广播到房间；
    收到远端 mutation 时 `commandService.executeCommand(..., { onlyLocal:true 之外的远端标记 })` 应用；
    防抖将整份快照 `saveSnapshot` 持久化到 SQLite（复刻参考项目"广播操作 + 存快照"模型）。
- **富文本**：`@tiptap/react` + `Yjs` + `y-protocols`。
  - 协作：Tiptap 官方 `Collaboration` 扩展绑定 Yjs `Doc`；自定义 `y-websocket` 兼容的
    provider 走同一个 `/ws` 服务（服务端做 Yjs update 中继 + 定时持久化 Y.Doc 编码到 SQLite）。
- 说明：两类编辑器共用同一 WebSocket 服务，但走不同子协议（表格=JSON 操作广播；富文本=Yjs 二进制中继），
  服务端按房间与消息类型分派。

### UI 风格
- Tailwind CSS v4，参考腾讯/金山文档：左侧/顶部导航 + 卡片式文档列表 + 干净的编辑器工作区。
- 组件化：顶栏、文档卡片、分享弹窗、权限选择、Toast 提示，配色以中性灰 + 品牌主色，圆角与轻阴影。

## 数据库设计（SQLite）

`src/server/db.ts` 启动时建表（`CREATE TABLE IF NOT EXISTS`）：

```sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE documents (
  id TEXT PRIMARY KEY,                 -- uuid
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'sheet',  -- 'sheet' | 'doc'
  owner_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  share_token TEXT UNIQUE,
  share_permission TEXT DEFAULT 'read',-- 'read' | 'edit'
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE document_snapshots (
  doc_id TEXT PRIMARY KEY REFERENCES documents(id) ON DELETE CASCADE,
  content TEXT NOT NULL,               -- 表格: JSON快照; 富文本: Tiptap JSON 或 Yjs base64
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE document_shares (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  doc_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  shared_with INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  permission TEXT NOT NULL,            -- 'read' | 'edit'
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(doc_id, shared_with)
);

CREATE TABLE document_edit_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  doc_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,
  username TEXT,
  edit_time TEXT NOT NULL DEFAULT (datetime('now')),
  edit_type TEXT DEFAULT 'edit'
);
```

## 具体改动 / 新建（Proposed Changes）

> 全部为新建文件（工作目录当前仅有参考 zip 与提示词），不修改参考项目。

### 1. 工程初始化
- 用 `create-next-app`（Next 16 / TS / Tailwind v4 / App Router）初始化到当前目录。
- 安装依赖：
  - 运行时：`better-sqlite3`、`iron-session`、`bcryptjs`、`uuid`、`ws`、`exceljs`
  - 编辑器：`@univerjs/*`（presets 表格套件）、`@tiptap/react @tiptap/starter-kit @tiptap/extension-collaboration`、`yjs`、`y-protocols`、`lib0`
  - 开发：`tsx`（运行 `server.ts`）、`@types/better-sqlite3`、`@types/ws`、`@types/bcryptjs`
- 修改 `package.json` scripts：`dev`/`start` 指向自定义服务器（`tsx server.ts`），`build` 走 `next build`。

### 2. 自定义服务器 `server.ts`
- 创建 HTTP server → `next({ dev }).getRequestHandler()` 处理常规请求。
- 在同端口挂载 `ws` 服务：`server.on('upgrade')`，仅处理 `/ws` 路径升级。
- 连接握手时解析 `?docId=&type=&token=`：
  - 校验会话或分享 token → 决定可读/可写；只读连接不接受写操作广播。
- 交给 `roomHub` 管理房间。

### 3. 协作中枢 `src/server/ws/roomHub.ts`
- 维护 `Map<docId, Set<WebSocket>>`。
- 表格通道：收到操作 JSON → 广播给同房间其余成员；防抖将快照落 `document_snapshots`。
- 富文本通道：Yjs sync 协议（`y-protocols/sync` + awareness）中继二进制；定时把 `Y.encodeStateAsUpdate` 存库；
  新连接时从库恢复初始 update 下发。
- 心跳：兼容 `ping/pong`（替代参考项目的 `rub`）。
- 写入日志 `document_edit_logs`。

### 4. 数据与认证
- `src/server/db.ts`：初始化 + 仓储函数（users/documents/snapshots/shares/logs 的 CRUD）。
- `src/server/session.ts`：`iron-session` 配置（cookie 名、密钥读环境变量，提供默认开发密钥）。
- `src/server/auth.ts`：`registerUser` / `verifyLogin` / `changePassword`（bcrypt）。

### 5. API Route Handlers（`src/app/api/**`）
- 认证：`register`/`login`/`logout`/`change-password`（对齐参考项目返回"重定向 URL / 错误信息"语义，但用标准 JSON + 状态码）。
- 文档：列表/新建、详情/删除、快照 GET/PUT、按用户名分享、分享链接生成/获取、分享访问校验、导出 xlsx。
- 所有写操作校验会话或分享权限（复刻参考项目 `login_required` 与只读/编辑控制）。

### 6. 页面（`src/app/**`）
- 登录/注册/改密：优雅表单，错误内联提示（复刻参考页面能力，UI 升级）。
- `documents/`：顶栏（用户名/改密/登出）+ "新建"下拉（表格 / 富文本）+ 文档卡片列表（名称/类型图标/更新时间/分享/删除）+ 分享弹窗（按用户名 & 生成链接、一键复制）。
- `sheet/[id]`：`SheetEditor`（Univer）+ 保存/导出/打印 + 在线协作状态。
- `doc/[id]`：`DocEditor`（Tiptap）+ 富文本工具栏 + 协作光标。
- `share/[token]`：按 `share_permission` 决定只读或可编辑，加载对应编辑器。

### 7. 编辑器封装（client components）
- `editors/SheetEditor.tsx`：初始化 Univer，注入快照，桥接 WebSocket 操作广播/应用，防抖保存。
- `editors/DocEditor.tsx`：Tiptap + Collaboration 扩展 + 自建 WebSocket provider（对接 `/ws` Yjs 通道）。

### 8. 样式
- `globals.css` 引入 Tailwind v4（`@import "tailwindcss";`）+ Univer/Tiptap 必要样式。
- 统一设计令牌（颜色/圆角/阴影/间距），组件级 Tailwind 类；参考腾讯/金山文档的简洁风。

## 假设与决策（Assumptions & Decisions）

1. **不引入 Redis**：用内存房间 + SQLite 快照替代参考项目的 Redis 角色（单机部署足够；简化依赖）。
2. **实时协作双通道**：表格走"操作广播 + 快照"（复刻参考模型）；富文本走 Yjs CRDT（更适合文本、冲突更少）。
3. **表格引擎选 Univer**（Luckysheet 官方继任者、TS/React 原生）；若安装或体积有阻塞，回退为内置轻量网格组件（保底可编辑 + 快照协作）。
4. **会话用 iron-session 加密 Cookie**，不建会话表；密码 `bcryptjs` 哈希（对齐参考的 Django 加密登录）。
5. **"更多"文档类型**（PPT/思维导图）仅在"新建"入口与类型枚举中预留，不实现编辑器。
6. **导出**：表格用 `exceljs` 生成 xlsx（对齐参考 openpyxl 导出）；富文本暂不做导出（如需可后续加）。
7. `data/`、`.env*`、`node_modules` 加入 `.gitignore`；提供 `.env.example`（`SESSION_SECRET`）。

## 验证步骤（Verification）

1. `npm install` 成功；`npm run dev` 启动自定义服务器（Next + WS 同端口）无报错。
2. `npm run build` 通过（类型检查、构建成功）。
3. 功能走查：
   - 注册 → 登录 → 进入文档列表。
   - 新建表格：编辑单元格 → 刷新后内容保留（快照持久化）→ 导出 xlsx 成功。
   - 新建富文本：输入内容 → 刷新保留。
   - 实时协作：两个浏览器窗口打开同一文档，一端编辑另一端实时看到变化。
   - 分享：按用户名分享给另一账户，对方列表可见并按权限访问；生成只读/可编辑链接，匿名/他人按权限访问。
   - 删除文档、修改密码、登出正常。
4. 权限校验：只读分享无法写入；未登录访问受保护页面被重定向到登录。
